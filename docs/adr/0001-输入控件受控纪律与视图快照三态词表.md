# 输入控件受控纪律

模型服务分区文本输入一律受控 value=、真相在视图模型；defaultValue 非受控形态禁用。

为什么：非受控输入没有 DOM 写回通道——保存成功后清空草稿（如 apiKey 输入）时界面停留在旧值，用户看到与落盘不符的状态（AX1 清场失效先例）。改回非受控会复活同类缺陷（难逆）；不写明则后来者会按 React 惯例选 defaultValue（无上下文会惊讶）；代价是组件夹具需重渲染语义配合（真实权衡）。

# 视图快照三态词表

三个视图快照（providers / models / routes）统一 `loading | ready | unavailable` 词表，失败态渲染显式提示与重试入口，不得把失败静默折叠成残缺数据。

为什么：models 视图曾把读取失败 catch 成 undefined 后 continue，用户看到「部分模型」而不知读取失败（静默残缺先例）。词表统一后三视图失败形态一致，新视图照词表走不再各自发明。
